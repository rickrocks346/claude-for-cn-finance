# 金融数据清洗

> 本 skill 为通用工具，与具体金融市场无关。适用于各类金融数据表格的标准化清洗。

## 概述

将用户上传的金融数据表格清洗为标准化的分析可用格式。处理缺失值、重复数据、格式不一致、单位不统一、代码格式错误等问题。

## 清洗维度

### 1. 数据完整性

| 问题类型 | 检测方法 | 处理策略（默认） | 替代策略 |
|---------|---------|---------------|---------|
| 整列为空 | col.nunique() = 0 | 删除列 | 标记待用户确认 |
| 行级缺失率 > 50% | row.isna().sum() / n_cols | 标记该行，询问是否删除 | — |
| 关键字段缺失 | symbol/date 为空 | **标记整行，不参与分析** | 不可填充（关键字段必须完整） |
| 财务数据缺失 | 某个报告期的某项指标缺失 | 时间序列：线性插值（2 个点以内）、前值填充（>2 个点） | 行业均值填充（需标注） |
| 截面数据缺失 | 可比公司中某家某个指标缺失 | 行业中位数填充（**必须标注**） | 删除该公司 |

**缺失值处理的黄金法则**：
- 关键字段（代码、日期）→ 绝不自动填充，标记为无效
- 财务数据 → 优先插值，其次中位数填充，**必须记录处理日志**
- 填充值超过数据的 20% → 该字段不建议用于严谨分析

### 2. 数据一致性

| 问题类型 | 识别特征 | 标准化方法 |
|---------|---------|----------|
| 金额单位混用 | 同一列数值范围差异极大（有些>1e8, 有些<1000） | 统一为"亿元"：<1e4 → ×1e-8, <1e8 → ×1e-4, 默认=亿元 |
| 日期格式混用 | YYYYMMDD, YYYY-MM-DD, YYYY/MM/DD, "2024年12月31日" | 统一为 YYYY-MM-DD |
| 股票代码格式 | 600519, 600519.SH, SH600519, 600519.XSHG | 统一为 6 位数字（核心代码），交易所后缀单独存储 |
| 行业分类不一致 | 同一个行业在不同系统中的名称不同 | 映射到申万 2021 版标准名称 |
| 正负号惯例不一致 | 费用类科目有正有负 | 统一：收入/利润为正，费用/成本为正（在利润表中默认均为正，减项通过公式处理） |
| 报表口径不一致 | 合并 vs 母公司，数据差大但无标注 | 识别"归属于母公司"关键词、金额数量级差异，添加 `report_type` 列 |

### 3. 数据准确性

| 校验类型 | 检测方法 | 阈值 |
|---------|---------|------|
| BS 平衡校验 | abs(总资产 - 总负债 - 所有者权益) / 总资产 | > 1% → 标记异常 |
| 增长率一致性 | (本期 - 上期)/abs(上期) vs 披露的增长率 | > 0.1% 偏差 → 标记 |
| 极值/异常值 | 中位数 ± 5×IQR 或超过行业均值 ± 5σ | 标记为异常值，建议人工复核 |
| 行业合理性 | ROE > 100% 或 < -100%，毛利率 > 95% 或 < -50% | 标记（某些行业可能合理，需人工确认） |
| 符号异常 | 常用利润类科目为负（除非亏损），资产类科目为负 | 标记 |

### 4. 数据可比性

| 维度 | 处理方法 |
|------|---------|
| 会计准则 | 添加 `accounting_standard` 列：CAS / IFRS / US GAAP / 未标注 |
| 报表类型 | 添加 `report_type` 列：合并 / 母公司 / 未标注 |
| 报告期 | 添加 `report_period` 列：Q1 / H1 / Q3 / FY（含年度） |
| 币种 | 添加 `currency` 列，多币种按当日汇率或用户指定汇率换算 |

## 金融数据清洗流水线

```
输入数据
 ↓
[Step 1] 扫描与概览
  - 行数、列数、各列类型、缺失率、重复率
  - 输出"数据概览"供用户确认
 ↓
[Step 2] 用户确认（交互环节，不可跳过）
  - 确认数据类型（财报/行情/基金净值/持仓/宏观）
  - 确认单位（元/万元/亿元）
  - 确认缺失值处理策略
  - 确认异常值阈值
 ↓
[Step 3] 自动清洗
  - 缺失值处理
  - 重复行去重
  - 格式统一（日期/代码/单位）
  - 行业分类映射
  - 异常值标记（不删除）
 ↓
[Step 4] 校验
  - 三表勾稽校验（如适用）
  - 增长率一致性校验
  - 极值合理性标记
 ↓
[Step 5] 输出
  - 清洗后数据 + 清洗报告 + 异常值标记清单
```

## 中国金融数据特有问题的处理

| 问题 | 描述 | 处理方法 |
|------|------|---------|
| 财报单位为"元" | 上市公司原始报表单位为元 | 自动转换为亿元（除以 1e8） |
| 股票代码前缀 | 上交所 6 开头，深交所 0/3/2 开头 | 添加 `exchange` 列：SH / SZ / BJ |
| 行业分类差异 | 同一只股票在申万/中信/GICS 分类不同 | 默认用申万 2021，保留原始分类 |
| 会计准则混合 | A+H 公司可能提供两套报表 | 默认取 CAS 合并报表 |
| Tushare 返回格式 | ts_code = "600519.SH" | 拆分为 code=600519, exchange=SH |
| AKShare 返回格式 | 列名可能为中文 | 保留中文列名，同时添加英文映射 |

## 数据质量评分

清洗完成后对数据集做综合评分：
| 维度 | 权重 | 评分方法 |
|------|------|---------|
| 完整性 | 30% | 1 - (缺失值数 / 总单元格数) |
| 一致性 | 25% | 通过一致性校验的比例 |
| 准确性 | 25% | 通过勾稽校验的比例 |
| 可比性 | 20% | 标注比例（会计准则/报表类型/报告期） |
| **综合评分** | — | < 0.6: 低质量, 0.6-0.8: 可接受, > 0.8: 高质量 |

## 分析流程

1. 扫描数据，生成数据概览（行数、列数、各列类型、缺失率）
2. 与用户确认清洗策略（数据类型、单位、缺失值处理方式、异常值阈值）
3. 执行自动清洗流水线
4. 校验数据准确性
5. 输出清洗报告 + 清洗后数据 + 数据质量评分

## 输出格式

```
## 数据清洗报告

### 数据概览
- 原始: X 行 × Y 列 | 总单元格: Z
- 清洗后: X' 行 × Y' 列
- 删除行: D 行（原因：缺失关键字段）
- 数据质量: X/1.0 (高质量/可接受/低质量)

### 清洗操作记录
| 操作 | 影响 | 说明 |
|------|------|------|
| 缺失值填充 | 15 行, 3 列 | 应收账款周转率用行业中位数填充 [已标注] |
| 去重 | 3 行 | 发现 3 组完全重复行 |
| 单位统一 | 42 行 | 从"元"统一为"亿元" |
| 行业映射 | 8 行 | 从 GICS 映射到申万 2021 |
| 异常值标记 | 5 个值 | 标记为人工复核 (详见清单) |

### 异常值标记清单
| 行 | 列 | 值 | 偏离度 | 建议 |
|----|-----|-----|--------|------|
| 23 | 毛利率 | -150% | 极端 | 建议人工复核，可能数据错误 |
```
